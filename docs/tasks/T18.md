# T18 — Regenerating submission evaluation results

Goal: Regenerate the evaluation outputs using the corrected metric semantics from T17 and ensure the submission status accurately reflects evidence and remaining external deliverables.

Create or edit
- scripts/eval.py
- eval/results.json
- docs/eval/report.md
- SUBMISSION_STATUS.md

Read
- scripts/eval.py
- eval/results.json
- docs/eval/report.md
- SUBMISSION_STATUS.md
- README.md (only the evaluation workflow and setup instructions)

Scope
- Preserve all existing unrelated worktree changes. Do not edit `board.json` or `NOW.md` manually.
- Use the already prepared local dataset/manifest if present. Do not download or commit raw dataset files unless the task owner explicitly authorizes it.
- If live evaluation requires network access, use only the existing `HF_API_KEY` from the local `.env` as a secret. Never print, echo, log, or copy any key/token into files or output. Do not display `.env` contents.
- Run a benchmark with the current T17 metric semantics and regenerate machine-readable results and the human-readable report only from actual run outputs. If the dataset, network, credentials, or running services prevent this, document the exact blocker without inventing results.
- Make case categories and metric denominators explicit: labeled documents/fields, completed jobs, processing failures, upload rejections, timeouts, and validation/fixture cases. Do not conflate generated fixtures with labeled accuracy samples.
- Ensure the accuracy section reports the sample count and field-level counts. Do not tune the extraction prompt/model against this evaluation set or pursue 100% by weakening comparisons.
- Update `SUBMISSION_STATUS.md` to map the assessment criteria to verified evidence, actual metrics if newly measured, and remaining user actions. Do not claim a walkthrough recording exists unless verified; do not make unsupported production-scale/security claims.
- Do not commit changes or modify other files.

Check
```bash
PYTHONPATH=src uv run pytest tests/test_eval.py
```

Done when
- The offline evaluation tests pass.
- Report and results agree and are reproducible from the run output, or they clearly state that a live rerun was blocked and retain no falsely implied refreshed metrics.
- The status document accurately distinguishes implementation completion from evidence and external submission deliverables.
